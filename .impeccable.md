## Design Context

### Users
Solo researchers (historians, journalists, organizers, theorists) engaging in deep-focus sessions with a knowledge vault containing curated works — e.g., a historian querying Lenin's collected writings, a journalist developing an analysis piece using reference materials as a thought partner. Vaults can be shared across a team but the interaction model is individual, contemplative, and intellectually demanding. Users are in a state of focused inquiry — not rushed, but engaged. Sessions range from quick lookups to multi-hour deep dives.

### Brand Personality
**Scholarly, refined, dynamic.** The interface should feel like a serious research instrument — the digital equivalent of a well-appointed reading room with a capable research assistant. Restrained but not cold. Alive but not playful. The warmth of paper and ink, the precision of good typography, the quiet confidence of a tool that knows its domain.

### Aesthetic Direction
- **Visual tone**: Editorial warmth — think letterpress, library reading rooms, fine book design. Dark backgrounds with warm gold accents. The color system already captures this well with the ink/warm/gold token scales.
- **References**: The tactile quality of a well-bound book. The information density of a broadsheet. The quiet competence of a research librarian.
- **Anti-references**: Notion (too generic, too colorful, too "blocks"), Obsidian (too plugin-aesthetic, too graph-as-gimmick), any SaaS dashboard with cards and metric tiles.
- **Theme**: Dark-first, matching deep-focus nighttime/morning research sessions. Light theme as alternative, not default.
- **Typography**: Libre Baskerville (body, reading, warmth) + JetBrains Mono Variable (chrome, UI, precision). Fonts are fixed — the pairing is intentional and working.

### Design Principles
1. **One surface** — The interface is a single integrated plane. Avoid modals, popovers, and page navigations. Transitions should feel like the same surface reorganizing itself (e.g., query bar becoming a top bar on the session page).
2. **Hunger over politeness** — The interface should feel like it wants content. Drop zones shouldn't politely accept; they should feel ready, capable, eager. The system has appetite.
3. **Depth through progressive disclosure** — Start minimal, reveal complexity only when the user engages. A circle becomes a zone. A status line becomes a pipeline. Complexity is earned through interaction, not presented upfront.
4. **Every state is designed** — Empty, loading, error, edge, success — all intentional, all warm, all helpful. No blank screens. No cryptic errors. No "nothing here" dead ends.
5. **Speed through calm** — The interface should feel fast without feeling rushed. Use smooth transitions, staggered reveals, and clear status communication to make waiting feel like watching something work, not staring at a spinner.
